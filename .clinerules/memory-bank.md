# 知识库读写强制规则（memory-bank）

本节是**硬性要求**：每个任务都必须执行，不因任务大小而豁免。
知识库本体在仓库根 `memory-bank/`，协议与索引见 `memory-bank/README.md`。

## 1. 任务开始（动手之前先做这一步）

1. **必读** `memory-bank/README.md`（协议 + 「症状 → 条目」索引），然后按任务关键词检索
   `memory-bank/issues-solved.md` / `pitfalls.md` / `decisions.md`：
   - 检索词优先级：报错原文 / 退出码 → 文件名·命令（`build.bat`、`build_pub_get.ps1`…）→
     症状词（卡死、挂死、黑屏、秒完、OOM、静默、跳过）→ 模块名（构建、播放器、导入、导出）
   - 方式：**优先 `read_files` 整篇读这 4 个文件**（体量小、最可靠）；
     `search_codebase` 在本仓库常超时、`findstr` 搜中文会假阴性，只作辅助（见 `PIT-019`）
2. **命中即复用**：直接按条目里的「修法 / 正确做法 / 决策」执行，**不要重新排查**，
   不要重复扫仓库、日志、HANDOFF 长文。
3. **老问题复发**：先跑条目里的「复发判据」（通常是一条命令）定论，确认后**更新原条目**
   （追加"最近复核 + 新证据"），**禁止新建重复条目**。
4. 条目与当前现场**矛盾**时：以现场证据为准重新排查，并在同一次任务内把条目改成与事实一致。
5. 回复里用**一句话报告查库结论**：命中了哪些条目编号；全部未命中就说"未命中，按新问题排查"。

## 2. 任务结束（必须回填，不许只做不写）

按 `memory-bank/README.md` §5 的模板追加或更新条目：

| 本次产生了什么 | 写到哪 |
| --- | --- |
| 定位清楚的问题（症状 → 根因 → 证据 → 修法 → 复发判据） | `issues-solved.md`（`ISSUE-nnn`，编号递增） |
| 踩的坑（命令语法 / 编码 / 工具怪癖 / 误判 / 被工具打断） | `pitfalls.md`（`PIT-nnn`） |
| 做的取舍（选型、方案对比、明确"不做"的范围） | `decisions.md`（`ADR-nnn`） |
| 老问题复发 | 更新**原条目**（不新建） |
| 没定位清楚的东西 | 可建条目，但必须标 `状态: 未定位` + 已知证据 + 下一步验证方法 |

- 每次新增条目都要同步更新 `memory-bank/README.md` §4 的「症状 → 条目」索引表。
- 模板里的「**复发判据**」「**反例 / 易误判**」「**正确做法**」三栏**不许省** —— 这三栏才是省时间的地方。
- 条目里**禁止**写 token / 密钥 / 私密凭据；本机固定工具路径（`D:\Tools\DevTools\...`）可以写。
- 收尾回复里必须包含：**本次更新了 memory-bank 的哪些条目**（编号 + 一句话）。

## 3. 质量红线

- 不许把"还没验证的猜测"写成结论；结论必须带证据（日志原文 / `文件:行` / 命令输出）。
- 不许删旧条目、不许改编号；**状态**可以改：`已修复` / `已规避` / `未修复` / `未定位`。
- 不许把整篇长文档复制进来：完整推导留在 `docs/HANDOFF-*.md`，条目里写「过程详见 `docs/xxx.md`」。
- 编码约定：`memory-bank/*.md` = UTF-8（**无 BOM**）+ CRLF，与 `README.md`、`.clinerules/` 保持一致。
- 新增/改名 `scripts\` 下的辅助脚本、或改动 `build.bat` 的脚本路径时，
  必须回看 `ISSUE-011`（"静默降级"事故）并跑它的复发判据。

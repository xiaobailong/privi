索引在 `README.md`；读取规矩与红线在 `.clinerules/memory-bank.md`。

## 1. 模板（照抄）
```
## ISSUE-nnn <一句话现象>
- 状态: 已修复|已规避|未修复|未定位　- 复发判据: <一条命令 + 期望输出，5 秒定论>
- 症状 / 根因 / 证据（日志原文 · `文件:行` · commit 哈希）/ 修法 / 反例（曾误判成什么）
- 相关条目　- 首次记录: YYYY-MM-DD ／ 最近复核: YYYY-MM-DD（结果）
```
```
## PIT-nnn <一句话坑>
- 触发条件　- 现象　- 正确做法（可直接复制）　- 反例（别这么写）　- 自检
```
```
## ADR-nnn <决策标题>
- 日期 | 状态: 已采纳|已废弃（被 ADR-xxx 取代）|待决
- 背景 / 决策 / 理由 / 备选与为何不选 / 影响与约束
```

## 2. 写到哪 / 必填栏
| 本次产生了什么 | 目标 | 必填 |
| --- | --- | --- |
| 定位清楚的问题 | `issues-solved.md`（`ISSUE-nnn`，编号 +1） | 复发判据 + 反例 |
| 踩的坑 | `pitfalls.md`（`PIT-nnn`） | 正确做法 + 反例 |
| 做的取舍 | `decisions.md`（`ADR-nnn`） | 备选与为何不选 + 影响 |
| 老问题复发 | **更新原条目**（不新建） | 追加「最近复核 + 新证据」 |
| 没定位清楚 | 可建条目 | 标 `状态: 未定位` + 已知证据 + 下一步验证 |

收尾动作：更新 `README.md` 索引 → 回复里列出本次条目编号 → 说明 `tmp\` 是否已清空。

## 3. 归档与压缩（控 token 的关键动作）
- **判据**（满足其一）：①主文件超上限（索引 2.5KB，本文件 4KB，`I` / `P` / `D` 各 12KB）；②条目「最近复核」> 90 天且已修复 / 已废弃；
  ③细节很长但只在极端场景才需要（如"三次失败方案"的过程分析）。
- **动作**：原文**逐字搬**到 `archive/<主文件名>-archive.md`（倒序追加），主文件原位置换一行摘要：
  `## PIT-nnn <坑> — 已归档（YYYY-MM-DD）：见 archive/pitfalls-archive.md；要点 + 自检：<一行>`
- **禁区**：不许改编号、不许丢「复发判据」；`archive/` 不进索引、默认不读；主文件始终保持"当前最有用的一屏"。

## 4. 红线（写条目前先看）
- 不许把没验证的猜测写成结论；结论必须带证据（日志原文 / `文件:行` / 命令输出 / commit 哈希）。
- 不许删条目、不许改编号；状态可改（`已修复` / `已规避` / `未修复` / `未定位`）。
- 条目只写结论 + 判据；长推导进 `archive/` 或 `docs\`，条目里给指针。**禁止粘贴完整日志 / 长堆栈**。
- 禁止写 token / 密钥 / 凭据（含 GitHub PAT）；本机固定工具路径（`D:\Tools\DevTools\...`）可以写。
- **会话压缩是有损的**：`/smol`、Auto-Compact、`/newtask` 只留摘要 ——
  关键结论与复发判据必须**当场**写进 memory-bank，不要指望靠会话摘要留存。
- 编码：`.clinerules/*.md`、`memory-bank/*.md` = UTF-8（无 BOM）+ CRLF（见 `PIT-002`）。
- 自检（临时脚本放 `tmp\`，用完即删）：bytes / ~tok 是否超阈值 + `enc=noBOM CRLF` + 交叉引用无悬空编号。

# memory-bank — 跨会话知识库（Cline 开工必读 / 收工必写）

> 目的：**同一个坑不查第二遍。** 已经定位清楚的问题、踩过的坑、做过的技术决策全部沉淀在这里；
> 配合 `.clinerules` 强制 Cline 每次任务开始读取、任务结束回填，跨会话复用，不再重复扫描老问题。
>
> 建立：2026-09-22　维护：Cline 每次任务自动更新　编码约定：UTF-8（无 BOM）+ CRLF（与 README/.clinerules 一致）

## 1. 固定文件（不要再加层级/新分类，加条目即可）

| 文件 | 内容 | 什么时候写 |
| --- | --- | --- |
| `README.md` | 本协议 + 「症状 → 条目」快速索引 | 每次新增条目时同步更新索引（§4） |
| `issues-solved.md` | **已排查问题**：症状 → 根因 → 证据 → 修法 → 复发判据（`ISSUE-nnn`） | 一个「卡住/失败/异常现象」被定位清楚之后 |
| `pitfalls.md` | **踩坑记录**：本机环境 / 工具链 / 命令语法陷阱（`PIT-nnn`） | 踩到一次就记，不管问题最终有没有修好 |
| `decisions.md` | **技术决策**（ADR 风格：背景/决策/理由/备选/影响，`ADR-nnn`） | 做了取舍、定了方案，或明确「决定不做」时 |

## 2. 开工协议（每个任务都要做，不许跳）

1. **先读本文件**（索引见 §4），再按任务关键词**去库里查**：命中就**直接复用结论**，不要重新排查。
2. 检索词优先级：报错原文 / 退出码 → 文件名·命令（`build.bat`、`build_pub_get.ps1`…）→
   症状词（卡死、挂死、黑屏、秒完、闪退、OOM、跳过、静默）→ 模块名（构建、播放器、导出、导入）。
   检索方式：**优先用 `read_files` 把 4 个文件整篇读**（合计约 50KB，最可靠）；
   `search_codebase` 在本仓库经常 30s 超时、cmd 的 `findstr` 搜中文关键词会**假阴性**，
   两者都只能当辅助（详见 `PIT-019`）。
3. 任务涉及的文件/现象若已有条目：**先按条目的结论执行**；只有当"当前现场证据"与条目矛盾时，
   才重新排查，并在同一轮内**更新该条目**（写清新证据）。
4. **老问题复发**：先跑条目里的「复发判据」（一条命令定论），确认后**更新原条目**（最近复核 + 新证据），
   **不要新建重复条目**。
5. 若条目给的是「已规避」而不是「已修复」，说明根因不可控（例如本机 WMI）：不要试图"真正修好"，
   按规避手段走即可。

## 3. 收工协议（每个任务结束前）

- 本次**定位清楚的问题** → 追加到 `issues-solved.md`；老问题复发 → 更新原条目。
- 本次**踩的坑**（命令语法、编码、工具怪癖、误判、被工具打断） → 追加到 `pitfalls.md`。
- 本次**做的取舍**（选型、方案对比、明确不做的范围） → 追加到 `decisions.md`。
- **没定位清楚的不许写成结论**：可以建条目但 `状态: 未定位`，并写清已知证据与下一步验证方法。
- 更新 §4 索引表（新条目必须能被关键词检索到）。
- 不写 token / 密钥 / 私密凭据；本机固定工具路径（`D:\Tools\DevTools\...`）可以写。
- 条目里优先写「复发判据」和「反例/易误判」——这两栏才是省时间的地方。

## 5. 条目模板（照抄，不要自由发挥）

**issues-solved.md**

```
## ISSUE-nnn <一句话现象>
- 状态: 已修复 | 已规避 | 未修复（待决）| 未定位
- 症状 / 现场: <看到什么，日志最后一行是什么>
- 复发判据: <一条命令 + 期望输出/退出码，5 秒定论>
- 根因: ...
- 证据: <日志原文 / 文件:行 / 命令输出>
- 修法: <改了哪个文件，怎么改；或规避手段>
- 反例 / 易误判: <曾经误判成什么>
- 相关文件: ...
- 首次记录: YYYY-MM-DD ／ 最近复核: YYYY-MM-DD（结果）
```

**pitfalls.md**

```
## PIT-nnn <一句话坑>
- 触发条件: ...
- 错误现象: ...
- 正确做法: <可直接复制的代码/命令>
- 反例（别这么写）: <代码/命令>
- 自检: <怎么确认自己没踩>
```

**decisions.md**

```
## ADR-nnn <决策标题>
- 日期 | 状态: 已采纳 | 已废弃（被 ADR-xxx 取代）| 待决
- 背景: ...
- 决策: ...
- 理由: ...
- 备选与为何不选: ...
- 影响 / 约束（后续改动必须注意）: ...
```

## 6. 与 `docs/HANDOFF-*.md` 的关系

- `docs/` 是**过程记录**（一次性交接文档，已被 `.gitignore` 忽略、不进 git，且不会被 `flutter clean` 删）。
- `memory-bank/` 是**结论索引**（进 git、跨会话跨机器复用，每次任务自动维护）。
- 完整推导过程留在 HANDOFF / 日志里没问题，但**结论、复发判据必须回填到 memory-bank**，
  并在条目里注明「过程详见 docs/xxx.md」，这样下次不必再读长文。
